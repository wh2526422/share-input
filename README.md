# 🎉 跨平台输入设备共享系统 - 最终版

一套完整的跨平台输入设备共享解决方案，支持在不同设备间共享鼠标、键盘、剪贴板和文件。

编译为免装 Python 的桌面程序，使用 `build_macos.sh`、`build_linux.sh`、`build_windows.ps1`。
构建依赖、发布目录与配置路径见 [BUILDING.md](BUILDING.md)。

## ✨ 核心功能

- 🖱️ **鼠标共享** - 完整的鼠标移动、点击和滚轮支持
- ⌨️ **键盘共享** - 所有按键和组合键支持（包括Ctrl, Alt, Shift, Tab等）
- 📐 **智能屏幕映射** - 自动适配不同分辨率，支持多显示器
- 📋 **剪贴板同步** - 服务端和所有已连接客户端自动同步文本
- 📁 **文件传输** - 服务端可选择一台或所有客户端作为接收方
- 💬 **文本消息** - 实时文本聊天
- 🔗 **连接管理** - 服务器地址输入、历史记录、断开重连
- 🔄 **断线重连** - 支持无限次重连，状态自动恢复
- 🎨 **图形界面** - 直观易用的GUI

## 🚀 快速开始

### 安装依赖

```bash
python3 -m pip install -r requirements.txt
```

图形界面使用 PySide6 / Qt（Essentials），不再需要 tkinter。更新时同步源码，并在每台电脑上用启动软件的同一个 Python 安装依赖；命令行入口不需要启动 Qt 窗口。

跨系统复制时，请排除 `.qt-deps/`、`.venv/` 和 `__pycache__/`。这些目录包含本机依赖或缓存，不能在 macOS、Linux、Windows 之间复用。程序只使用当前 Python 环境中的 Qt，不再自动加载项目里的 `.qt-deps`。

Linux 若出现 `Shiboken.abi3.so: invalid ELF header`，先更新 `src/qt_runtime.py`，再运行上面的安装命令。旧 `.qt-deps` 可以留着，更新后的程序会忽略它。也可使用独立环境安装并启动：

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python main.py
```

Linux/X11 还需要系统的 xcb 运行库。如果启动时提示 `xcb-cursor0 or libxcb-cursor0 is needed`，Ubuntu/Debian 可执行：

```bash
sudo apt update
sudo apt install libxcb-cursor0
python main.py
```

`pip` 只安装 Python/Qt 包，不会安装上述系统库。程序现在会在创建 Qt 窗口前检查 xcb 插件依赖；如果还缺其他库，会显示实际加载错误和对应插件的 `ldd` 检查命令。其他发行版请安装对应的 xcb cursor 运行库。依赖列表见 [Qt Linux requirements](https://doc.qt.io/qt-6/linux-requirements.html)。

Python 3.10/3.11 请避开 PySide6 / shiboken6 6.12.0：该版本的已知引用计数缺陷可导致 `none_dealloc: deallocating None` 崩溃（[PYSIDE-3474](https://qt-project.atlassian.net/browse/PYSIDE-3474)）。`requirements.txt` 已排除该版本，启动时也会检查。已安装该版本的电脑请退出软件，更新源码后使用同一个 Python 重新安装依赖并重启：

```bash
python -m pip install --upgrade --force-reinstall -r requirements.txt
python main.py
```

### 启动服务端

```bash
python3 server.py
```

多台客户端可以同时连接同一个服务端。“设备”页显示在线设备、地址、系统和分辨率，可发送文件、查看远程桌面或分别共享键盘、鼠标；选择目标时支持多选设备或所有在线客户端，查看远程桌面为单选。
左侧导航提供设备、剪贴板、消息、连接信息和运行日志，底部显示本机设备名和局域网 IPv4 地址。使用 `python3 main.py` 可在同一窗口右上角切换服务端和客户端。

### 启动客户端

```bash
python client.py
```

在客户端GUI中：
1. 输入服务器IP地址（例如：192.168.10.162）
2. 点击"连接"按钮
3. 连接成功后即可使用

## 🎮 使用方法

### 独立共享键盘和鼠标

- 点击“开始共享键盘”转发按键到客户端当前获得焦点的应用。
- 点击“开始共享鼠标”转发移动、点击和滚轮。
- 连接多台设备时，每个按钮都可以选择一台或所有在线客户端。键盘和鼠标可以同时共享，目标可以不同，本地输入也继续生效。
- 再次点击对应的“停止共享”按钮即可停止该设备的共享。某台客户端断开时，其余已选目标继续接收输入。新连接的客户端在下次选中后才会加入共享。

客户端也有“开始共享键盘”和“开始共享鼠标”按钮，可分别把输入共享给当前连接的服务端。两端更新后启用。同一类输入切换共享来源时会停止原方向并释放按住的键鼠，进入投屏时会停止普通键鼠共享。

设备正在接收远端键盘或鼠标共享时，对应按钮会独立置灰并显示“被共享中”，另一类按钮不受影响。共享停止或连接断开后恢复。此状态需要两端新版完成能力协商；旧端仍可共享输入，但不能通知接收方显示该状态。

### 远程桌面

1. 两端用各自运行程序的 Python 安装 `requirements.txt` 中的依赖并重启。
2. 服务端点击“查看并控制客户端”并选择一台设备，或在客户端点击“查看并控制服务端”。发起时选择分辨率上限（720p、1080p、1440p 或 4K）。
3. 服务端和客户端互相查看时都可直接进入。两端更新后，发起端可选择对端显示器，并通过投屏窗口顶部“控制 → 显示器”实时切换。
4. 投屏窗口会等比显示画面，顶部悬浮控制条显示“控制”菜单、实际像素尺寸、帧率和网络往返延迟。通过“控制”菜单可调整显示器、分辨率和帧率，或结束投屏。帧率可选 15、30、45 或 60 帧/秒，新版之间默认 30 帧/秒，连接旧版时默认 15 帧/秒。窗口内可以点击、滚动和输入。按 Shift+Esc 暂停控制，点击画面恢复。任一端可在主界面点击“结束投屏”，查看端也可以关闭投屏窗口。
5. 普通窗口和全屏下，悬浮控制条默认自动隐藏，鼠标移到画面顶部会显示，移开或关闭菜单后再次隐藏。点击“固定”可保持悬浮条显示，按钮变为“已固定”；再次点击恢复自动隐藏，切换全屏时保留固定状态。点击悬浮条的“全屏”或按 F11 进入全屏，点击“退出全屏”或再按 F11 恢复窗口。F11 仅操作本机窗口，操作菜单前会释放远端按住的键鼠。

网络延迟通过独立的小数据连接每秒测量，显示网络往返耗时。采集、编码和窗口绘制还会影响操作反馈。画面允许最多两帧流水发送，使采集与传输重叠，并限制旧画面积压。

两端均支持音频时，投屏收到首帧后会自动连接远端声音。点击悬浮条的声音按钮可关闭本次投屏的声音，在「控制 → 远端音量」可以单独调节控制端的播放音量。音频连接中断时会自动重连，连续三次重连失败后可点击声音按钮再试。系统声音经独立连接传输，远端仍照常播放，麦克风不参与采集。网络拥塞时会跳过积压的声音，画面和键鼠无需等音频。双声道有声时约占 1.54 Mbps，PCM 静音包只发包头。连接旧版仍可正常投屏。

被控端 macOS 13 及以上使用 ScreenCaptureKit，Windows 使用默认播放设备的 WASAPI 回环。Linux/X11 使用默认输出的监听源，可使用 PulseAudio 或 PipeWire。Ubuntu/Debian 的 PulseAudio 或 PipeWire-Pulse 环境可安装 `pulseaudio-utils`，原生 PipeWire 路径需要 `wpctl` 和 `pw-record`。

“运行日志”默认保留连接、错误、采集后端及编码器信息；高频投屏性能日志默认关闭，需要排查时勾选该页的“显示投屏性能日志”。普通日志仍限制为最近 1000 行。

服务端和客户端每次开始共享鼠标时都会询问源屏幕宽高，以上次输入值为默认；停止共享时不询问，取消输入不会启动共享。悬浮控制条的固定、全屏按钮使用图标，悬停可查看操作提示；固定后的图标高亮，全屏后图标切换为退出全屏。

Windows/Linux 远程窗口控制 Mac 时，Caps Lock 优先复用单独共享键盘所用的原生键盘监听，按下、松开和源端时间一起传给 Mac，避免 Qt 锁定键事件配对差异将短按当成长按。仅投屏窗口正在控制且有焦点时转发，Qt 路径不再重复发送此键；离开窗口或暂停控制会取消未完成的按压。短按仍遵循 Mac 的输入法设置，长按仍可切换大写锁定。

Windows 和 Linux/X11 控制 Mac 时，还会去掉 Qt 字母文本中本机 Caps Lock 带来的大小写反转，保留 Shift 和键盘布局本身的结果，由 Mac 决定远端输入法及大写锁定状态。Windows 原生监听使用消息入队时间，Linux 使用 X11 原始事件时间判断按压间隔，避免回调排队被误算成长按；Linux 时间采集不依赖 pynput 是否提供小键盘映射表。

Mac 接收普通英文字母时，按未移位字母查找实体键位，并沿用按下时的键位发送松开。
这同时作用于独立键盘共享和远程控制，避免源端 Caps Lock 产生的大写字母进入 Unicode 文本回退，
出现“图标已切回拼音，但只能直接输入英文”的问题。Shift、Command 和 Mac 的大写锁定仍由事件标志保留。

采集/编码与网络发送由两个线程并行执行，待发送区只保留最新一张 JPEG。网络暂时变慢时，新画面覆盖尚未发送的旧画面，避免恢复后补播过期内容；已经开始写入 TCP 的帧仍须完整发送。切换显示器/分辨率会丢弃旧配置的待发画面，保持设置确认与新画面的发送顺序。Windows 采集线程优先使用独立的高精度计时器限速，不修改系统全局计时精度；静止桌面暂时没有更新时，不额外再睡一个帧周期。

JPEG 优先通过 libturbojpeg 原生接口复用压缩器和输出缓冲，直接编码采集到的 BGRA，原生调用释放 GIL。默认质量仍为 85、4:4:4，使用快速整数 DCT；缺少加速库或编码失败时回退到 Pillow。源码运行可选安装加速 wheel：

```sh
python -m pip install --only-binary=:all: turbojpeg==0.0.2
```

没有匹配当前 Python/架构的 wheel 时，继续使用 Pillow 即可；不需要为可选加速在本机编译依赖。新版构建脚本会自动尝试安装并打包加速库。运行日志会明确打印采集后端、JPEG 编码器及回退原因。

如果远端本机已立即响应，但返回的画面滞后，请查看两端“运行日志”中的“投屏性能”：记录统计期间的平均画面更新率、设定帧率上限、数据速率、平均每帧大小，以及采集/编码、编码后待发、发送缓冲写入、收帧等待、解码、界面图像转换、绘制的平均/最大耗时。发送端额外记录替换掉的未发送旧帧数；采集/编码耗时也包含随后被替换的帧，不能与成功发送帧数直接相乘推导总耗时。收帧等待包含等待下一帧，发送耗时只到本机发送缓冲，二者都不是网络 RTT。日志通常每 5 秒输出；完全没有画面帧的静止期会延长统计窗口。无线网络的小包往返快，也可能在持续传大画面时吞吐不足。日志保留最近 1000 行，性能统计只保留累计值。

发送端还会拆分记录“读屏、转色、缩放、JPEG编码”；“采集/编码”是这些阶段的合计，不能重复相加。首帧发送后记录原始采集像素尺寸、目标上限、Pillow 版本和 libjpeg-turbo 状态。macOS Retina 的原生采集、缩放与转色合在“读屏”一项中。

macOS 优先使用 ScreenCaptureKit 按设定帧率连续采集，由系统按目标像素尺寸缩放，回调只保留最新原生样本，消费时才复制、转色或直接送入 JPEG 编码器。源码运行需更新 `requirements.txt` 中的 macOS 依赖，Nuitka 构建会自动安装对应框架封装。日志记为“ScreenCaptureKit取帧/转色”；缺少依赖、系统不支持或采集失败时回退到 CoreGraphics/MSS，并在运行日志显示具体原因。Retina 输出按物理像素上限计算，保留原有等比显示和实时帧率切换。

Windows 优先使用 DXGI Desktop Duplication 采集，需缩小时由 Direct3D 11 在 GPU 上等比缩放，再只读回目标尺寸的像素、编码 JPEG。日志合记为“DXGI采集/GPU缩放/读回”。不额外安装 NumPy 或 OpenCV，不使用后台抓帧队列；GPU 纹理和读回缓冲区在同一会话内复用，结束或切换显示器、分辨率时释放。新版协议在桌面静止时不重复编码、发送旧画面，旧协议每秒重发一次缓存图像保活。因此“实际 fps”是画面的发送频率；选择的 15/30/45/60 fps 是上限，采集、编码和网络速度决定能否达到，日志同时记录设定上限。

DXGI 不可用、桌面失效或采集异常时，会回退到 GDI/MSS，并在启动终端打印原因。GDI 在需要降采样时使用目标大小的缓冲区，采集、缩放和转色合记为“原生读屏/缩放/转色”。“等候画面确认”是两帧发送额度用尽后等对端解码确认的时间，“帧率限速等候”是按所选帧率主动等待的时间，“等候桌面更新”表示 DXGI 暂无新画面；这些等待均不计入“采集/编码”，也不是独立的网络 RTT。

每端同时支持一个单屏投屏会话，画面最高 3840×2160、60 帧/秒。实际尺寸受对端屏幕像素数和宽高比限制，实际帧率取决于采集、编解码和网络速度。对端未支持分辨率协商时使用 720p。投屏和可选的音频子连接复用同一 TCP 端口。服务端开始投屏时会结束正在进行的普通键鼠共享。

采屏支持 macOS、Windows 和 Linux/X11。macOS 被查看端需要屏幕录制和辅助功能权限。Linux Wayland 采屏尚未接入。当前投屏数据通过未加密的 TCP 连接传输，请在可信局域网内使用。

用 Mac 控制 Linux/X11 时，Control 对应 Ctrl，Option 对应 Alt，Command 对应 Super。复制和粘贴使用 Control+C/V。

在 Linux 投屏窗口里控制 Mac 时，Win+C／Win+V 对应 Mac 的 ⌘C／⌘V。Qt 窗口保留左右 Super/Meta 键，并根据事件中的修饰键状态补齐漏收的按下事件。控制 Linux/X11 上的投屏画面时会抓取键盘，让 Alt+Tab 等组合键交给远端；按 Shift+Esc、打开控制菜单、失焦或关闭窗口会释放抓取和按住的键。点击画面恢复控制。也可使用“控制”菜单里的“复制 ⌘C”“粘贴 ⌘V”。

按键含义与单独共享键盘一致：Win/Super 对应 Command，Alt 对应 Option。因此 Mac 的默认应用切换快捷键 ⌘Tab 对应 Win+Tab；Alt+Tab 传送的是 Option+Tab。

### Linux 键盘 → macOS 客户端

- Win / Super → Command（⌘），Alt → Option（⌥），Ctrl → Control（⌃），Shift → Shift（⇧）。左右修饰键分别保留。
- 例如复制使用 Win+C（Mac 的 Command+C），Ctrl+C 仍是 Control+C。
- Mac 合成的鼠标按下、拖动、松开和滚轮事件会在发出前合并远端 Command/Shift/Ctrl/Option 状态。Linux/X11 控制画面同时抓取键盘和鼠标，移出画面、进入控制条或按 Shift+Esc 释放。
- 共享键盘配合 Mac 本地鼠标时，鼠标拦截器合并远端修饰键的通用标志及左右键状态位；键盘的 flagsChanged 事件使用同一套状态。松开一个 Shift 时仍保留另一个按住的 Shift，鼠标事件已有的本机修饰键状态也会保留。
- Mac 远控点击使用本次请求的位置，原地松开不会额外生成拖动；按下/松开携带一致的点击次数。投屏窗口直接传递双击标记，避免收包间隔影响双击识别；两端需同步更新。
- Mac 开启系统“使用大写锁定键切换到 ABC 输入法”时，远端 Caps Lock 短按优先触发系统配置的输入源切换快捷键（默认 Control＋空格），由 macOS 处理输入法切换和拼音模式；自定义快捷键会跟随系统设置，临时使用的修饰键会在切换后恢复。两个输入源快捷键均禁用时保留 IOHIDSystem Caps 系统键路径，不使用 TISSelectInputSource 只选择输入源。启用多个输入源时，短按会遵循系统快捷键的选择顺序。长按至少 0.5 秒在松开时切换大写锁定，已锁定时短按只解锁。长按只按发送端原始事件时间判断（投屏窗口使用 Qt 事件时间，Linux X11 键盘共享使用 X server 事件时间），网络延迟或接收端界面排队不计入按压时长。两端都需更新；旧端或缺少可靠源端时间的按键按短按处理，不再凭收包间隔猜测长按。系统偏好关闭时保留普通 Caps Lock 行为。断线和停止共享会取消未完成的 Caps 按下，不误切输入法。
- Mac 接收的普通滚轮按每格 3 行换算为原生离散行事件，投屏窗口快速滚动会拆包保留总格数。若要调整 Mac 端手感，可在 Mac 的 `config.json` 增加 `"mac_scroll_lines_per_notch": 6`（整数 1–20，默认 3），重启 Mac 软件生效。Mac → Linux 的每格换算不变。不同应用和系统滚动加速仍可能导致实际页面距离有差异。
- 建议更新两端并重启。原始虚拟键码现在携带来源平台，避免 Linux 键码被误当成 macOS 键码。
- Wayland 全局捕获限制仍然存在：服务端未捕获的按键无法由客户端恢复。

### Ubuntu 自动隐藏 Dock

Ubuntu GNOME 默认 Dock 若启用 `require-pressure-to-show`，光标到边缘后还需继续向外推才能显示。当前远程桌面使用绝对坐标定位，不能表达这段越过边界的推力。可以保留自动隐藏，仅关闭压力要求，让到达边缘即可显示：

```bash
gsettings get org.gnome.shell.extensions.dash-to-dock require-pressure-to-show
gsettings set org.gnome.shell.extensions.dash-to-dock require-pressure-to-show false
```

如需恢复原来的压力触发，设回 `true`。这是用户可选的桌面设置，程序不会自动修改。

### 屏幕映射

**多显示器支持**：
- 首次共享鼠标时，会询问主显示器分辨率
- 输入你要用来控制的显示器尺寸（默认1920x1080）
- 鼠标位置会自动按比例映射到客户端

**示例**：
- 主显示器：1920x1080
- 客户端：1536x864
- 映射比例：自动计算为 0.800
- 效果：主显示器最右边 → 客户端最右边 ✅

### 文件传输

**发送文件**：
1. 点击"发送文件"按钮（服务端或客户端都可以）
2. 从服务端发送时，先在设备弹框中选择一台或所有客户端，再选择文件。客户端发送时直接选择文件。
3. 对方选择保存位置后，文件通过独立连接传输，进度窗口显示已传字节。
4. 对方保存完成后，发送端显示完成。

大文件需要两端更新。新版向旧版发送时，单个文件上限为 256 KiB。

### 文本消息

1. 切换到"文本消息"标签页
2. 输入文字
3. 点击"发送"或按回车
4. 对方立即收到

### 剪贴板同步

在服务端或任一已连接客户端复制文本，内容会同步到其他在线设备。新客户端会收到服务端当前的共享文本。

## 💡 使用技巧

### 1. 快速切换服务器
客户端支持连接历史记录，可以从下拉框快速选择之前连接过的服务器。

### 2. 文件传输
- 支持任何类型的文件
- 可以选择保存位置和重命名
- 后台处理，不影响其他操作
- 带进度条显示

### 3. 屏幕坐标映射
**自动适配不同分辨率**：
- 服务端和客户端屏幕大小不同时，鼠标位置会自动按比例映射
- 支持多显示器，只需设置主显示器尺寸
- 无需任何配置，连接时自动计算比例

### 4. 多设备管理
命令行服务端也支持多个客户端和组内剪贴板同步。若要用方向键切换控制，可用 `python3 src/server.py --client <设备名或IP>` 指定目标。设备选择弹框、文件传输和向所有设备共享键鼠使用图形界面。

## 🐛 故障排除

### 连接失败

**检查**：
- 服务端是否已启动
- IP地址是否正确
- 防火墙是否允许端口9999
- 两台设备是否在同一局域网

### 鼠标不移动

**验证方法**：
- 在客户端打开记事本
- 在服务端打字
- 如果文字出现，说明功能正常（鼠标可能不明显）

### macOS 服务端监听兼容

macOS 服务端使用项目内的 `MacKeyboardListener`，跳过 pynput 监听线程中未被按键解析使用的输入源查询，避免 `TSMGetInputSourceProperty` / `dispatch_assert_queue` 崩溃。全局键盘监听仍然启用；不需要修改系统安装的 pynput。当前原生验证版本为 pynput 1.8.1。

可在 Mac 上运行 `python3 tests/macos_server_smoke.py`，验证首次连接、空剪贴板消息和重连。测试使用随机 localhost 端口，不发送鼠标或键盘输入。
